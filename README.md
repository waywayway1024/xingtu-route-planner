# 行途 · 国内路线规划网页

原生 HTML / CSS / JavaScript，无第三方 npm 依赖。地图、地点搜索和路线数据来自高德地图 JS API 2.0；它们是在线服务，不是本地开源路线引擎。

本项目代码使用 MIT 许可证，见 LICENSE。高德地图 SDK、地图数据及在线服务不包含在本项目的 MIT 授权中，使用者需自行申请 Key，并遵循高德的服务条款、配额及授权要求。

## 启动

在本文件夹打开终端，执行：

```powershell
node server.cjs
```

打开 http://localhost:8080 。无需执行 npm install。也可以执行 `npm start`。不要直接双击 HTML；使用本地 HTTP 服务更可靠。端口占用时可先运行 `$env:PORT = '8081'`，再启动服务。

## 配置高德地图

1. 访问 https://lbs.amap.com/ ，注册并进入控制台。
2. 创建应用并申请 **Web 端（JS API）** 类型的 Key，同时取得安全密钥（securityJsCode）。不是 Web 服务 API 类型。
3. 打开网页右上角「地图设置」，填写 Key 和安全密钥，点击「保存并连接」。配置保存在当前浏览器的 sessionStorage 中，刷新后仍有效，关闭会话后可能需要重新填写。
4. 如果你的 Key 启用了域名限制，请配置实际使用的域名，并确保本地测试地址符合控制台的限制。

也可以编辑 `config.js` 的 `key`、`securityJsCode`、`defaultCity`。配置文件会被浏览器读取，不要将填过真实安全密钥的文件上传到公开仓库。

正式部署建议按高德官方说明配置服务端安全代理，并在 `serviceHost` 填入 `https://你的域名/_AMapService`。本项目附带的 server.cjs 仅为本地静态服务器，没有实现安全代理。代理所需安全密钥应留在服务器，具体路径转发、额度与商业授权以高德官方文档和控制台为准。

## 使用

右上角「English / 中文」可即时切换中英文界面，并保存语言偏好。按钮、输入提示、状态、进度、错误提示、路线摘要、推荐顺序和复制行程随语言切换；已输入的地址、已确认位置和路线保留，不重新加载地图或重新查询。高德提供的地点名称、地图标注和导航详情可能仍为中文，地址不会被自动翻译。

右上角「黑夜模式」可切换深色界面与深色地图；切换后按钮变为「日间模式」。界面先响应，地图样式在界面绘制后稍作延迟更新，快速连续点击只应用最后选择的地图样式，已应用的样式不会重复加载。主题偏好延后保存，并在离开页面时补存；下次打开自动恢复。首次访问默认跟随系统的深浅色偏好。地图本身的样式加载耗时仍取决于高德服务、网络和设备。

- 填写搜索城市，再输入起点和终点。地址查询结果会列出详细位置，点击候选地点确认，避免同名地点选错。
- 驾车、公交、步行和骑行四种方式；驾车支持速度优先、费用优先、距离优先和躲避拥堵。
- 点击「规划路线」，地图展示线路，左侧显示预计耗时、距离和高德提供的详细方案。
- 交换起终点；可授权浏览器定位，将当前位置设为起点。
- 公交规划需填写城市。路线是否可用取决于高德服务覆盖范围。
- 支持手机和桌面网页。定位需要浏览器权限，公网部署请使用 HTTPS。

页面不会模拟真实路线。没有 Key、服务额度不足、网络失败或没有可用路线时，会显示对应提示。预计耗时是规划参考，不提供持续 GPS 跟随、语音播报或自动偏航重算。

## 部署与验证

### Sites 分享版

已增加 Cloudflare Workers 兼容的部署版本，运行 `npm run build` 生成 `dist/server/index.js`。线上通过 `/site-config.js` 自动加载服务器配置，安全密钥不会发送到浏览器；地址与路线查询经本站 `/_AMapService` 转发到高德。线上配置完成后，访问者无需输入自己的 Key。

服务器环境变量为 `AMAP_JS_KEY`（JS API Key）与 `AMAP_SECURITY_CODE`（安全密钥，按 secret 保存）。不要把安全密钥填写到公开源码。`deployment-secrets.local.json` 已忽略，仅用于本地交接部署配置。高德控制台如果设置了域名限制，需要允许发布后的站点域名。

### 多地址自动排序

点击「＋ 添加地址」添加途经地址，每个地址都需从候选地点中确认。最多支持 8 个地址（起点、终点和 6 个中间地址）。选择驾车后可按总耗时或总距离优化：默认固定起点、终点，只调整中间地址；选择「最后一站不限」后，起点固定，其余地址都参与排序。

点击「批量输入」可一次粘贴 2–8 行地址，空行自动忽略。导入会替换当前地址，第一行是起点、最后一行是终点；点击各地址并选择候选地点完成确认。每个地址下方显示确认状态，列表显示已确认数量。按住途经地址右上角「⠿ 拖动」，拖到另一地址的上半部或下半部，松开即可插入到该地址之前或之后。拖动时有插入位置提示，移动后保留已确认位置，起点和终点不参与拖动。拖出地址区域松开则取消；键盘用户可聚焦拖动手柄后使用上下方向键排序。修改顺序后需重新规划。

规划期间显示道路查询进度，可点击「取消计算」。正在进行的单次查询可能需要结束或超时后才完全停止，之后不会再查询剩余路段。修改地址或选项也会使旧计算失效。推荐结果列出地点及详细地址，可「复制行程」，或「将顺序填回地址栏」继续调整和重新规划；复制需要浏览器剪贴板权限，在 localhost 或 HTTPS 使用。

系统逐对查询实际驾车路段，保留道路方向差异，再用动态规划计算本次分段成本矩阵中的最优访问顺序，最后生成经过全部地址的完整驾车路线。页面显示顺序及相较输入顺序的分段估算改善。该结果不等同于实时交通条件下的全局最优，也不考虑停留时间、营业时间、送达时限或车辆容量。暂不提供多地址公交、步行和骑行优化。

查询量随地址数量增长；8 个地址时，固定终点约 43 次、最后一站不限约 50 次调用（含最终完整路线）。顺序查询并限速，可能需要几十秒；部分账号额度或频率限制可能阻止规划。查询失败会提示错误，不会用直线距离替代道路结果。编辑地址或选项会使正在计算的结果失效。

运行 `npm test` 验证优化算法、部署代理及规划交互回归，包括固定/自由终点、有向道路、不可达和重复位置，随机矩阵与穷举最优值对比，以及导入校验、已确认地址排序、取消计算后丢弃旧结果。交互回归使用模拟地图服务，不请求实际高德路线。

将 index.html、styles.css、app.js、i18n.js、route-optimizer.js、config.js 放到静态网站服务中即可。正式部署需设置域名、HTTPS 与安全代理。现有分享站点：https://xingtu-route-planner.chenyukhang1024.chatgpt.site 。本次优化先在本地试用，尚未同步到分享站点。

语法检查：`npm run check`。真实服务验收需要有效 Key：分别测试四种模式、地址候选选择、同名地址、起终点交换、定位拒绝、无路线及失效 Key。
