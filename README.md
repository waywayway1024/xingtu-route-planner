# manmanhang · 国内路线规划网页

原生 HTML / CSS / JavaScript，无第三方 npm 依赖。地图、地点搜索和路线数据来自高德地图 JS API 2.0；它们是在线服务，不是本地开源路线引擎。

本项目代码使用 MIT 许可证，见 LICENSE。高德地图 SDK、地图数据及在线服务不包含在本项目的 MIT 授权中，使用者需自行申请 Key，并遵循高德的服务条款、配额及授权要求。

## v1.2.1 部署更新

新增 [香港 / Linux 服务器部署脚本与说明](hongkong-deploy/README.md)，包含 Nginx、systemd 和空凭据模板。**下载源码必须配置使用者自己的高德 Key 及安全密钥**；源码不提供作者的高德凭据，也不默认连接作者的地图代理。**打开作者分享的网址则使用线上服务器的配置**，访客无需填写 Key。

## v1.2.0 地图功能

- **持续定位与方向箭头**：点击「定位我」持续更新位置，显示精度圈；「回到位置」将地图移回当前点。「开启方向」需另行授权，箭头表示手机屏幕顶部朝向。后台暂停采集，回到页面后恢复。
- **两个独立规划面板**：「从当前位置出发」只需确认目的地，以点击规划时的最新有效位置作为起点；「自定义路线」保留手动地址、批量导入、途经点排序和地图点选。两个面板保留各自输入与出行设置。
- **自动安排游玩路线**：在自定义面板一次输入 2–8 个地点，按实际驾车耗时或距离选择出发地点、结束地点和访问顺序，无需返回第一站。同名地点需手动确认。
- **定位与搜索稳定性优化**：坐标转换串行执行，失败有界重试；搜索合并重复请求，切换面板或修改输入后屏蔽迟到结果；相同状态减少重复界面更新。

手机使用：[打开正式版 manmanhang](https://way1024.site/)，在系统和浏览器中允许定位，再点击「定位我」；需要方向箭头时点击「开启方向」。网站无需登录 ChatGPT。定位、方向和剪贴板需要浏览器相应权限，公网使用需 HTTPS。

位置超过 30 秒未更新时不能用于新路线；方向数据超过 5 秒失效，不会用旧方向继续显示有效朝向。手机应尽量平放，屏幕顶部指向前方。方向权限拒绝不会阻止定位。移动后需再次点击规划，本版不提供语音导航或自动偏航重算。

完整版本记录、验证范围和使用限制见 [CHANGELOG.md](CHANGELOG.md)。

## 启动

在本文件夹打开终端，执行：

```powershell
node server.cjs
```

打开 http://localhost:8080 。无需执行 npm install。也可以执行 `npm start`。不要直接双击 HTML；使用本地 HTTP 服务更可靠。端口占用时可先运行 `$env:PORT = '8081'`，再启动服务。

## 配置高德地图

1. 访问 https://lbs.amap.com/ ，注册并进入控制台。
2. 创建应用并申请 **Web 端（JS API）** 类型的 Key，同时取得安全密钥（securityJsCode）。不是 Web 服务 API 类型。
3. 打开网页右上角「地图设置」，填写 Key 和安全密钥，点击「保存并连接」。配置保存在当前浏览器的 sessionStorage 中，刷新后仍有效，关闭会话后可能需要重新填写。
4. 如果你的 Key 启用了域名限制，请配置实际使用的域名，并确保本地测试地址符合控制台的限制。

也可以编辑 `config.js` 的 `key`、`securityJsCode`、`defaultCity`。配置文件会被浏览器读取，不要将填过真实安全密钥的文件上传到公开仓库。

正式部署建议按高德官方说明配置服务端安全代理，并在 `serviceHost` 填入 `https://你的域名/_AMapService`。本项目附带的 server.cjs 仅为本地静态服务器，没有实现安全代理。代理所需安全密钥应留在服务器，具体路径转发、额度与商业授权以高德官方文档和控制台为准。

## 使用

页面分为「从当前位置出发」和「自定义路线」两个独立面板。默认从当前位置出发：授权定位后，只需输入并确认目的地，可选择驾车、公交、步行和骑行。公交会识别出发城市，识别失败时可手动填写。两个面板保留各自输入，切换后需重新规划；原有自动安排游玩路线、批量输入、途经点排序和地图点选都在自定义路线面板中使用。

地图下方可开启持续定位、回到当前位置和方向箭头。定位使用浏览器 GPS，并转换为高德坐标；精度圈表示定位误差，超过 30 秒未更新的位置不能作为新的路线起点。方向需单独授权，箭头表示手机屏幕顶部朝向，请尽量平放手机。后台会暂停采集，回到页面后恢复；设备不支持方向传感器或拒绝方向权限时，定位仍可使用。路线采用点击规划时的位置，移动后可再次规划。

右上角「English / 中文」可即时切换中英文界面，并保存语言偏好。按钮、输入提示、状态、进度、错误提示、路线摘要、推荐顺序和复制行程随语言切换；已输入的地址、已确认位置和路线保留，不重新加载地图或重新查询。高德提供的地点名称、地图标注和导航详情可能仍为中文，地址不会被自动翻译。

右上角「黑夜模式」可切换深色界面与深色地图；切换后按钮变为「日间模式」。界面先响应，地图样式在界面绘制后稍作延迟更新，快速连续点击只应用最后选择的地图样式，已应用的样式不会重复加载。主题偏好延后保存，并在离开页面时补存；下次打开自动恢复。首次访问默认跟随系统的深浅色偏好。地图本身的样式加载耗时仍取决于高德服务、网络和设备。

- 填写搜索城市，再输入起点和终点。地址查询结果会列出详细位置，点击候选地点确认，避免同名地点选错。
- 驾车、公交、步行和骑行四种方式；驾车支持速度优先、费用优先、距离优先和躲避拥堵。
- 点击「规划路线」，地图展示线路，左侧显示预计耗时、距离和高德提供的详细方案。
- 交换起终点；可授权浏览器定位，将当前位置设为起点。
- 公交规划需填写城市。路线是否可用取决于高德服务覆盖范围。
- 支持手机和桌面网页。定位需要浏览器权限，公网部署请使用 HTTPS。

页面不会模拟真实路线。没有 Key、服务额度不足、网络失败或没有可用路线时，会显示对应提示。预计耗时是规划参考，不提供语音播报或自动偏航重算。手机访问需要 HTTPS，并在系统和浏览器中允许定位；电脑 localhost 可用于功能验证，真实 GPS 和朝向仍需手机验收。

## 部署与验证

### Sites 分享版

已增加 Cloudflare Workers 兼容的部署版本，运行 `npm run build` 生成 `dist/server/index.js`。线上通过 `/site-config.js` 自动加载服务器配置，安全密钥不会发送到浏览器；地址与路线查询经本站 `/_AMapService` 转发到高德。线上配置完成后，访问者无需输入自己的 Key。

服务器环境变量为 `AMAP_JS_KEY`（JS API Key）与 `AMAP_SECURITY_CODE`（安全密钥，按 secret 保存）。不要把安全密钥填写到公开源码。`deployment-secrets.local.json` 已忽略，仅用于本地交接部署配置。高德控制台如果设置了域名限制，需要允许发布后的站点域名。

### 香港 / Linux 服务器

见 [hongkong-deploy/README.md](hongkong-deploy/README.md)。下载者填写自己的凭据，配置自己的域名，再构建安装；真实私有配置与部署包不提交到 Git。服务器配置完成后，访客可直接打开分享网址。JS API Key 会由浏览器读取，安全密钥保留在服务器；建议设置高德域名白名单并监控配额。

### 多地址自动排序

顶部「游玩地点」输入框可一次填写 2–8 个地点，每行一个。选择总驾车耗时或总距离，点击「自动安排游玩路线」，程序会搜索并确认当前候选中唯一同名匹配的位置，再从全部地点中自动选择第一站和最后一站，安排无需返回起点的完整路线。同名地点会展开「手动输入或确认地点」，需要从详细候选中选择实际地点，然后再次点击自动安排继续。搜索城市用于缩小范围；此入口按驾车路线计算。

地图上的地点图标可点击查看名称和详细地址，再点击「确认添加」作为途经地点。取消不会添加；重复地点、读取失败和超过上限时不能添加。自动起终点模式会检查全部地点的重复情况；顶部文本与当前确认列表一致时，地图新添的地点会同步进顶部输入框。

点击「＋ 添加地址」添加途经地址，每个地址都需从候选地点中确认。最多支持 8 个地址（起点、终点和 6 个中间地址）。选择驾车后可按总耗时或总距离优化：默认固定起点、终点，只调整中间地址；选择「最后一站不限」后，起点固定，其余地址都参与排序。

点击「批量输入」可一次粘贴 2–8 行地址，空行自动忽略。导入会替换当前地址，依次填入地址栏，起终点按当前安排选项确定；点击各地址并选择候选地点完成确认。每个地址下方显示确认状态，列表显示已确认数量。按住途经地址右上角「⠿ 拖动」，拖到另一地址的上半部或下半部，松开即可插入到该地址之前或之后。拖动时有插入位置提示，移动后保留已确认位置，起点和终点不参与拖动。拖出地址区域松开则取消；键盘用户可聚焦拖动手柄后使用上下方向键排序。修改顺序后需重新规划。

规划期间显示道路查询进度，可点击「取消计算」。正在进行的单次查询可能需要结束或超时后才完全停止，之后不会再查询剩余路段。修改地址或选项也会使旧计算失效。推荐结果列出地点及详细地址，可「复制行程」，或「将顺序填回地址栏」继续调整和重新规划；复制需要浏览器剪贴板权限，在 localhost 或 HTTPS 使用。

系统逐对查询实际驾车路段，保留道路方向差异，再用动态规划计算本次分段成本矩阵中的最优访问顺序，最后生成经过全部地址的完整驾车路线。页面显示顺序及相较输入顺序的分段估算改善。该结果不等同于实时交通条件下的全局最优，也不考虑停留时间、营业时间、送达时限或车辆容量。暂不提供多地址公交、步行和骑行优化。

查询量随地址数量增长；8 个地址时，固定终点约 43 次、最后一站不限约 50 次、起终点都自动安排约 57 次道路调用（含最终完整路线，另有地点搜索）。顺序查询并限速，可能需要几十秒；部分账号额度或频率限制可能阻止规划。查询失败会提示错误，不会用直线距离替代道路结果。编辑地址或选项会使正在计算的结果失效。

运行 `npm test` 验证优化算法、部署代理及规划交互回归，包括固定/自由终点、有向道路、不可达和重复位置，随机矩阵与穷举最优值对比，以及导入校验、已确认地址排序、取消计算后丢弃旧结果。交互回归使用模拟地图服务，不请求实际高德路线。

将 index.html、styles.css、app.js、live-location.js、i18n.js、route-optimizer.js、config.js 放到静态网站服务中即可。正式部署需设置域名、HTTPS 与安全代理。现有分享站点：https://xingtu-route-planner.chenyukhang1024.chatgpt.site 。本地源码修改在发布后同步到分享站点。分享版也保留「地图设置」，可保存并优先使用个人 Key 及配套安全码或代理，配置仅保留在当前浏览器会话中。

语法检查：`npm run check`。真实服务验收需要有效 Key：分别测试四种模式、地址候选选择、同名地址、起终点交换、定位拒绝、无路线及失效 Key。
